Scaled Dot-Product Attention, Step by Step

Source: Attention Is All You Need · Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, Polosukhin · 2017 — Section 3.2.1 · Eq. (1)

1 · Start here

Attention maps a query and a set of key-value pairs to an output. Each query is compared with every key by a dot product; after dividing by sqrt(d_k) and applying softmax, the resulting weights say how much of each value vector to mix. The output is that weighted sum of the value vectors.

Why it matters

This single formula is the core operation of the Transformer: it lets every position gather information from all other positions in one parallel matrix multiply. The sqrt(d_k) scaling is what keeps the softmax trainable when key/query dimensions are large.

Symbols

Qmatrix of queries, one row per query position, each row of length dk
Kmatrix of keys, one row per key position, each row of length dk
Vmatrix of values, one row per key position, each row of length dv
dkdimension of queries and keys (number of columns of Q and K)
dvdimension of values (number of columns of V)
Sraw score matrix QKT, shape (queries x keys)
Aattention weight matrix after softmax, each row sums to 1
Ooutput matrix AV, one row per query

How it works, step by step

  1. Take one query row q and every key row kj; compute raw scores sj=q·kj (the matrix S=QKT).
  2. Divide each score by dk to get scaled logits zj=sj/dk.
  3. Apply softmax over the keys: aj=ezj/∑mezm, giving a row of weights that sums to 1.
  4. Form the output for that query as the weighted sum o=∑jajvj; stacking rows gives O=AV.
  5. Repeat for every query row; each row of A is an independent probability distribution over the keys.

    3 · Guided explorations

    1

    Equal scores give uniform weights

    Change
    Set all three rows of K equal (as in the preset) and keep scaling on.
    Observe
    Every raw score in a row is identical, so A has 1/3 in each cell and rowSums = 1 for both queries; O becomes the average of the three V rows, (0.667, 0.667).
    Why
    Softmax of equal logits is uniform, so the output is the plain mean of the values.
    2

    A dominant key and the role of sqrt(d_k)

    Change
    Give q1 a large dot product with k1 (preset), then toggle 'Divide scores by sqrt(d_k)' off.
    Observe
    With scaling on, z1 = 27/sqrt(3) = 15.59 and the weight on k1 is about 1.0 (maxWeight ~ 1). With scaling off, z1 = 27, the softmax is even more saturated, and the output row for q1 stays essentially v1 = (1, 0).
    Why
    Dividing by sqrt(d_k) shrinks logits so softmax keeps usable gradients; without it, large d_k pushes softmax into a near one-hot region.

    4 · Common misunderstanding

    The 1/dk factor is not a normalization of the output or of the values. It only rescales the logits before softmax; the weights still sum to 1 either way, but their sharpness changes. The paper's footnote 1 shows why: for independent unit-variance components, q·k has variance dk, so the logits grow like dk unless divided by it.

    5 · Source grounding

    Paper: Attention Is All You Need · Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, Polosukhin · 2017 — Section 3.2.1 · Eq. (1).

    From the paper

    • Attention maps a query and a set of key-value pairs to an output, where the output is a weighted sum of the values and the weight is a compatibility function of the query with the key (Section 3.2).
    • The input consists of queries and keys of dimension d_k and values of dimension d_v; dot products are divided by sqrt(d_k) and softmax gives the weights (Section 3.2.1).
    • Attention(Q,K,V) = softmax(QK^T/sqrt(d_k))V (Eq. 1).
    • For independent unit-variance components, the dot product has mean 0 and variance d_k, so scaling counteracts large logits (footnote 1).
    “We compute the dot products of the query with all keys, divide each by dk , and apply a softmax function to obtain the weights on the values.”
    “To counteract this effect, we scale the dot products by 1dk .”

    Our simplifications & examples

    • We use tiny editable matrices (2 queries, 3 keys, d_k = 3, d_v = 2) instead of the paper's d_k = d_v = 64 and h = 8 heads.
    • We add a softmax temperature T (default 1) purely as a teaching knob; the paper uses T = 1.
    • The sweep view varies T rather than d_k because d_k is fixed by the matrix shape in this toy.
    • No training, masking, positional encoding, or multi-head projection is shown.
